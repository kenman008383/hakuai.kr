# 새 강의 올리기

하쿠는 유튜브 주소만 준다(여러 개일 수 있음). 대본·자막 파일을 같이 주면 그걸 자막보다 우선한다.

## 1. 영상 정보와 자막 가져오기
```bash
python3 tools/fetch_video.py <주소> [<주소> ...]
```
- `tools/_work/<ID>/meta.json`, `transcript.txt`가 생긴다.
- 자막이 아직 없으면(업로드 직후) 하쿠에게 알리고, 대본이 있으면 받는다. 둘 다 없으면 제목·설명만으로 쓰지 말고, 몇 시간 뒤 다시 시도하겠다고 말한다.
- 하쿠는 보통 **복습 자료 PDF**를 함께 보낸다. 유튜브가 "Sign in to confirm you're not a bot"(로봇 확인)으로 막으면 **우회하지 않고**(다른 player client·쿠키 시도 금지) PDF를 보고 만든다. 이때는 영상 길이·구간 목차를 빼고, 영상 설명란에 '영상 순서'가 있으면 그것으로 목차를 만든다. PDF도 없으면 PDF나 대본을 달라고 한다.
- 따라 할 질문은 PDF 문장 그대로 쓴다. PDF 내용을 보고 질문 형태로 바꿔 쓴 것은 보고할 때 하쿠에게 알린다.
- 새 작업 창에는 도구가 없을 수 있다: `pip install python-pptx yt-dlp`, `apt-get install -y fonts-nanum && fc-cache -f` (LibreOffice는 기본 설치됨).

## 2. 과정·단계·번호 정하기
- 제목, 설명, 썸네일 문구의 "입문 01" 같은 표기를 우선한다(썸네일: `https://i.ytimg.com/vi/<ID>/maxresdefault.jpg`를 받아서 직접 본다).
- 표기가 없으면 같은 단계의 마지막 번호 + 1. 애매하면 하쿠에게 한 번 묻는다.
- 이미 있는 번호면 덮어쓰지 말고 하쿠에게 확인한다.

## 3. 강의 JSON 쓰기
`src/content/episodes/chatgpt/intro/00.json`과 같은 형식으로 `src/content/episodes/<과정>/<단계>/<번호>.json`을 만든다.

| 항목 | 쓰는 법 |
| --- | --- |
| `video`, `date`, `duration`, `ytTitle` | meta.json 그대로 |
| `tag` | 짧은 주제어 (예: "첫 질문") |
| `title` | 시청자에게 말 걸듯 한 줄. 썸네일 큰 글씨가 있으면 그 문구 |
| `coverLines` | 표지 2줄 이내, 강조할 말은 `**` |
| `subtitle`, `oneLine` | 한 줄 |
| `summary` | 2~4문장. 무엇을 배우고 왜 쓸모 있는지 |
| `goals` | `[제목, 설명]` 3개 |
| `timeline` | `[초, 소제목, 설명]` 6~8개. 자막 시간 기준, 영상 길이를 넘지 않게 |
| `prompts` | 영상 속 예시를 따라 할 질문 2~4개 `{label, text, after}` |
| `cautions` | `[제목, 설명]` 2~3개, 영상에서 강조한 주의점 |
| `practice` | "~했어요" 체크리스트 3~4개 |
| `next` | 영상 끝 예고 `{no, title}`. 예고가 없으면 빼기 |
| `slides` | 본문 슬라이드 3~6장 (`bullets` / `prompt` / `statement`, 형식은 `tools/make_slides.py` 위쪽 설명) |

- 자동 자막의 오타는 고쳐서 쓴다(예: "su 있는" → "수 있는"). 영상에 없는 사실은 넣지 않는다.
- 앞 편의 `next`가 이번 편을 가리키면 그대로 두어도 된다(사이트가 실제 강의 링크로 바꿔 보여 줌).

## 4. 슬라이드 만들기
```bash
python3 tools/make_slides.py src/content/episodes/<과정>/<단계>/<번호>.json
```
- **디자인은 챕터 안에서 고정이다.** 슬라이드 모양을 맞추려고 `tools/make_slides.py`의 색·글꼴·배치를 고치지 않는다. 넘치는 글자는 JSON 문장을 줄여서 해결한다. 디자인 변경은 하쿠가 지시할 때만(CLAUDE.md 규칙).
- PDF를 PNG로 몇 장 렌더링해서(`pdftoppm -r 40`) 글자가 상자를 넘거나 겹치는지 본다. 넘치면 JSON 문장을 줄인다.

## 5. 빌드하고 올리기
```bash
npm run build
git add src/content public/files && git commit -m "Add <과정> <단계> <번호>: <제목>" && git push origin main
```
- push 후 GitHub Actions 배포가 끝나면(1~3분) `https://hakuai.kr/<과정>/<단계>/<번호>/`가 열리는지 확인한다.

## 6. 하쿠에게 보고
- 공개된 주소, 각 편 제목 한 줄, 자막 오타나 확인이 필요한 부분.
- 유튜브 설명란 **맨 윗줄**에 넣을 문구 (2026-11-12 정함):
  `📘 강의 자료(PPT·PDF)와 따라 할 질문: https://hakuai.kr/<과정>/<단계>/<번호>/`
- 고정 댓글 문구: `이번 강의에서 쓴 질문 문장과 슬라이드는 여기서 받을 수 있어요 👉 https://hakuai.kr/<과정>/<단계>/<번호>/`
- 앞 편 끝의 '다음 강의' 안내를 이번 편으로 이었으면, 앞 편 슬라이드도 다시 만들어 함께 올리고 보고한다.

## 7. 기록 남기기
- `docs/작업기록.md` 맨 위에 기록하고, AI 회사 저장소의 p28도 고친다 (CLAUDE.md "기록 남기기").

## 부록: PC 폴더에서 여러 편을 한꺼번에 올릴 때 (2026-11-22 입문 10~24편 방식, 하쿠: "오늘처럼만 해줘")
하쿠가 "E:\하쿠영상\<단계>" 같은 PC 폴더를 알려 주고 맡기면 이 순서로 한다. 하쿠의 별도 지시가 없으면 아래 결정을 그대로 따른다.
1. 폴더 접근을 요청하고 편마다 `영상.mp4`·`게시정보.txt`·`썸네일.png`·`참조자료.pdf`를 확인한다. 유튜브 스튜디오에 이미 올라간 초안이 있는지 먼저 본다(있으면 새로 올리지 않고 이어서 마무리).
2. 크롬 파일 넣기는 3.8MB까지라 영상은 하쿠가 직접 골라야 한다. 영상 사본을 `<폴더>\_유튜브_올리기\<단계><번호>.mp4`로 모아 두고, 하쿠에게 업로드 창의 [파일 선택] → Ctrl+A → [열기] 한 번만 부탁한다.
3. 번호 순서대로 한 편씩: 제목·태그는 게시정보 그대로, 썸네일은 썸네일.png, 설명란 = 맨 윗줄 `📘 강의 자료(PPT·PDF)와 따라 할 질문: https://hakuai.kr/<과정>/<단계>/<번호>/` + [설명] + "영상 순서" + [영상 순서]. 공개, 아동용 아님(하쿠가 공개를 맡긴 경우에만 게시).
4. 고정 댓글 = [고정 댓글 초안], 띄어쓰기만 고친다(숫자·글자 붙은 곳). 달고 고정한다.
5. 홈페이지: 자막 대신 참조자료 PDF + 영상 순서 + 구간마다 영상 화면 한 장을 보고 JSON을 쓴다. 따라 할 질문 ① PDF 요청문+가상 자료 그대로 ② 영상 화면의 짧은 요청. 슬라이드 표지 썸네일은 썸네일.png(이 작업 공간은 i.ytimg.com이 막혀 있을 수 있음). 자료 카드는 3줄 이내로 짧게.
6. 게시정보·복습 PDF·썸네일은 `docs/자료/<과정>-<단계>-<번호>/`에 넣되, Drive 주소 같은 비공개 링크는 뺀다.
7. 빌드·push·배포 확인 → 작업기록·p28 반영 → 하쿠에게 "확인할 것"만 짧게 모아 보고한다.
